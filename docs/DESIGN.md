# Design notes

## What a chunker promises

A chunker turns a byte stream into a sequence of chunks. For every algorithm here:

- Chunks tile the input exactly: offsets are contiguous from 0 and the lengths sum to the input length.
- Every chunk except the last is at least `min_size` and every chunk is at most `max_size`.
- **Streaming invariance.** The boundaries do not depend on how the input is divided across `feed()`
  calls; feeding one byte at a time gives the same chunks as feeding the whole buffer.
- **Locality.** Whether a cut is made after a given byte depends only on the previous 64 bytes (Gear)
  or 48 bytes (Rabin), plus the size limits. This is what lets chunk boundaries re-align after an
  insertion or deletion, and it is also why bytes before `min_size - window` are skipped without hashing.

The last chunk of a stream ends at the end of the input, so it can be shorter than `min_size`.

## Gear chunker

The Gear hash of a window is `sum over j of table[b_j] << j` (mod 2^64), where `b_j` is the byte `j`
positions back; the rolling form is `fp = (fp << 1) + table[byte]`. Bit `k` depends on the last `k + 1`
bytes, so the cut mask uses the **top** bits of the word, which see the full 64-byte window.

Cut decision after adding a byte, with `L` the chunk length so far:

| L | action |
| --- | --- |
| `L < min_size` | keep going; no cut is possible |
| `min_size <= L < avg_size` | cut if `(fp & mask_strict) == 0`, where `mask_strict` has `log2(avg) + norm` bits |
| `avg_size <= L < max_size` | cut if `(fp & mask_relaxed) == 0`, where `mask_relaxed` has `log2(avg) - norm` bits |
| `L == max_size` | cut |

Making cuts rarer below the average and more likely above it is *normalized chunking* (FastCDC). It
does not change the mean much; it narrows the distribution (coefficient of variation 0.80 to 0.30 in
the [results](../README.md#results)) so fewer chunks are tiny or hit `max_size`.

Deviations from the FastCDC paper, all deliberate:

- Hashing starts at `min_size - 64` and is not restarted at `min_size`, so the hash at any cut point is
  exactly the hash of the last 64 bytes. That makes the locality property exact rather than approximate.
- The masks are runs of top bits instead of the spread bit patterns in the paper.
- The 256-entry table is generated by 256 successive splitmix64 outputs from `kGearSeed`, so it is
  reproducible without shipping a table, but boundaries will not match other FastCDC implementations.

## Rabin chunker

The fingerprint of a 48-byte window is the window read as a polynomial over GF(2) (first byte is the
highest degree), reduced modulo a fixed irreducible polynomial of degree 53, `0x3DA3358B4DC173`.
`tests/cross_check.py` verifies irreducibility with Rabin's test.

Rolling update in two table lookups per byte:

```
digest ^= out[byte leaving the window]          // out[b] = b * x^(8 * 47) mod p
digest  = ((digest << 8) | incoming) ^ mod[digest >> 45]   // mod[b] = reduction of the 8 bits above degree 53
```

A cut is made when `(digest & (avg_size - 1)) == 0`, subject to the same `min_size` / `max_size` rules.
There is no normalization: the size distribution is close to geometric above `min_size`.

## Fixed-size chunker

Blocks of exactly `avg_size` bytes. It exists as the baseline: one inserted byte moves every later block
boundary, so nothing after the edit deduplicates.

## Testing strategy

| Layer | What it catches |
| --- | --- |
| Property tests (`test_chunkers.cpp`) | tiling, size limits, streaming invariance, reuse after `finish()`, empty and short input, zeros and periodic data |
| Definition tests (`test_hash.cpp`) | rolling Gear and Rabin updates equal the hash computed from scratch from the window; the digest forgets bytes older than the window |
| Behaviour tests (`test_dedup.cpp`) | boundaries survive an insertion and a deletion, mean size is near the target, normalization narrows the distribution |
| Differential test (`tests/cross_check.py`) | 11 inputs and parameter sets produce the same chunk lengths as `tests/reference.py`, which computes every cut from the definition with no rolling state and shares no code with the library |
| Golden vectors (`test_golden.cpp`) | any change to the algorithm moves boundaries, which would invalidate stored chunk indexes |
| Mutation check (`tests/mutation_check.py`) | 18 deliberate bugs are each caught; 2 edits that cannot matter (state made irrelevant by the window) survive, as they should |
| Sanitizers | ASan and UBSan over the whole suite in CI |

## Limits

- Single-threaded, no SIMD. Chunking a large file in parallel needs a coordinator that splits at
  content-defined points; that is out of scope here.
- The tools identify chunks by 64-bit FNV-1a, which is fine for measuring overlap and not a substitute
  for a cryptographic hash in a real deduplicating store.
- `avg_size` must be a power of two and `min_size` at least 64.
